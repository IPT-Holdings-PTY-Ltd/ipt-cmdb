# Support

## Community and development support

Use GitHub issues for reproducible bugs and scoped feature requests that do not contain sensitive information. Include the application version/tag, deployment method, browser, relevant sanitized logs and clear reproduction steps.

Before opening an issue:

1. review [README.md](README.md) and the [documentation index](README.md#documentation);
2. check existing issues;
3. confirm the problem occurs on the latest supported build;
4. collect the `/api/health` response with secrets and internal hostnames removed;
5. reproduce with demo data where possible.

## Not suitable for public issues

Do not post:

- suspected security vulnerabilities;
- passwords, API keys or database URLs;
- customer names, exports or screenshots;
- Easy Auth principal payloads;
- Passportal data;
- proprietary provider payloads.

Report security issues privately according to [SECURITY.md](SECURITY.md).

## Operational incidents

This public repository is not an MSP service desk. Production incidents should follow the deploying organisation's incident, backup and escalation procedures.
